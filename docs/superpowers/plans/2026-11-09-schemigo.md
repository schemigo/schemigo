# Schemigo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать декларативный diff и применение схемы для PostgreSQL, MySQL и ClickHouse с Go API, CLI, экспортом, шаблонами, историей, блокировкой и снимками схемы.

**Architecture:** Общая модель `schemigo.Schema` и migration engine находятся в корневом пакете; диалекты реализуют introspection, diff, валидацию, историю и блокировку через один `Driver`. Сначала выпускается полный PostgreSQL-путь, затем отдельными рабочими этапами MySQL и ClickHouse. CLI загружает Go-схему через сгенерированный `schema/main.go`, который выводит JSON; программные пользователи передают `Schema` напрямую.

**Tech Stack:** Go 1.27, `database/sql`, `pgx/v5/stdlib`, `go-sql-driver/mysql`, `clickhouse-go/v2`, `chroma/v2`, `testcontainers-go`, `github.com/go-zookeeper/zk`; стандартные `flag`, `go/format`, `crypto/sha256`, без CLI- и ORM-фреймворков.

**Spec:** `SPEC.md`

## Предлагаемые уточнения спецификации

Это проектные решения для реализации, а не уже согласованные изменения требований:

- Убрать интерактивное редактирование SQL (`e`): править Go-схему и повторно строить план. Если редактирование требуется сохранить, отдельно определить проверку соответствия изменённого SQL желаемой схеме.
- Проверка без применения гарантирует валидность модели и построения плана; `EXPLAIN` не доказывает корректность DDL. Проверку реального результата и повторного запуска выполнять на одноразовых БД после снятия ограничения. Автоматический DOWN с восстановлением удалённых данных не обещать.
- Идемпотентность проверять на уровне результата и повторного запуска после сбоя. Одного `IF EXISTS` недостаточно: совпадающее имя может скрывать другое определение объекта.
- Снимок схемы не является резервной копией данных. Для зависимых views и enum не генерировать удаление неизвестных зависимостей; возвращать ошибку с перечислением препятствий.
- `Schema.Order` задаёт предпочтение между независимыми операциями. Зависимости имеют приоритет; невозможный порядок должен приводить к понятной ошибке.
- История служит журналом. Повторяющийся SQL-хеш не позволяет пропустить непустой текущий diff: объект мог быть изменён вручную после предыдущего применения.

## Global Constraints

- Версия модуля остаётся `go 1.27`; обычные тесты работают через `go test ./...` без Docker.
- Интеграционные тесты имеют `//go:build integration`, запускаются с `SCHEMIGO_TESTCONTAINERS=1` и не зависят от порядка выполнения.
- Порядок сущностей по умолчанию: **extensions → enums → tables → functions → triggers → views**; `Schema.Order` может его изменить.
- Идентификаторы всегда квотируются по правилам диалекта; schema и object name квотируются отдельно. Default, Expression, Using, Where и Definition остаются сырым SQL.
- Все операции используют `IF EXISTS` / `IF NOT EXISTS`; там, где MySQL не поддерживает такой синтаксис для `ALTER`, используется guard через `information_schema` и prepared DDL.
- Extensions create-only: лишние расширения не удаляются. Версии при экспорте не закрепляются.
- `schema_migrations` исключается из introspection/diff; хеш набора — SHA-256 от точных байтов `Plan.SQL()`. История допускает повторные применения одинакового SQL после drift; hash не является уникальным идентификатором события.
- Интерактивное редактирование `e` не реализуется: после ручного изменения SQL нельзя доказать соответствие Go-схеме. `SPEC.md` и CLI предлагают только `Y` и `n`; правка выполняется в Go-схеме с повторным diff.
- Dry-run ничего не изменяет: не создаёт историю/снимок, не берёт lock и не выполняет DDL. DDL и DO-блоки пропускаются при `EXPLAIN`; реальная проверка DDL выполняется интеграционными тестами на контейнерах.
- Снимок в `schemigo_backup/` содержит только схему, не данные. Он создаётся под lock до изменений, удаляется после успеха и сохраняется после ошибки.
- Любая ошибка CLI даёт exit code 1; отмена пользователем и «нет изменений» — 0.
- PostgreSQL поддерживает все сущности спецификации. MySQL отклоняет Extensions и отдельные Enum; ClickHouse отклоняет Extensions, Enum, ForeignKey и Trigger. Неподдерживаемая сущность — ошибка, а не молчаливый пропуск.
- Для ClickHouse `Table.Engine` обязателен; поддерживаются таблицы/колонки, skipping indexes, constraints, SQL functions, обычные и materialized views. Распределённый Apply без гарантированной блокировки запрещён.

## Review Focus

- **Неоднозначный rename:** несколько одинаковых кандидатов не должны превращаться в DROP данных; Task 5 проверяет отказ с понятной ошибкой.
- **Частично применённый DDL:** MySQL/ClickHouse не дают общей транзакции; Tasks 13 и 15 проверяют повторный запуск после сбоя без ручной чистки.
- **Зависимые views:** пересоздание должно восстановить управляемые зависимости; Task 7 проверяет replace, recreate и отказ при неизвестных зависимостях.
- **Снимок не восстанавливает данные:** ошибка Apply и документация не должны обещать полный backup; Task 9 проверяет текст с путём и ограничением.
- **Блокировка ClickHouse:** нельзя молча заменять межпроцессный lock локальным mutex; Task 15 проверяет два независимых соединения и отказ Apply при недоступном координаторе.

### Task 4: PostgreSQL quoting, extensions и enum diff

Реализовано: QuoteIdent/Qualified/QuoteLiteral, детерминированный dispatcher Diff, create-only extensions с pinned UPDATE, enum create/add/drop и атомарное пересоздание при удалении/перестановке значений. Для пересоздания читаются зависимости scalar/array-колонок и defaults; неизвестные зависимости отклоняются без CASCADE. DO-блок сохраняет комментарий и отказывает, если новый тип получает другой owner/ACL, в том числе из-за изменённых default privileges. Существующий временный тип не удаляется. Неподдерживаемые изменения остальных сущностей дают errors.ErrUnsupported. Normalize канонизирует пустые slices в nil для сравнения эквивалентных схем. Добавлен Statement.OutsideTransaction; будущий Apply обязан его учитывать. Код и тесты оставлены в рабочем дереве без нового коммита.
